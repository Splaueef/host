# Host

This repository contains files used for hosting services and resources related to Hikka-based projects.

⚠️ This is **not an official repository** of the original Hikka project.

This repository is a **mirror / convenience copy** created to keep hosting resources available and functional.  
The original repository was copied manually and uploaded as a separate project so the resources can continue working even if the original infrastructure becomes unavailable.

The purpose of this repository is to maintain hosting-related files used by custom builds, forks, and related tools.

## AirAlert

`airalert.py` читає повідомлення каналу `@air_alert_ua` та надсилає вибрані
тривоги через inline-бота Hikka і в додаткові чати. Акаунт Hikka має бути
підписаний на канал; для особистих повідомлень треба запустити свого inline-бота.

Налаштування відкриваються командою `.config AirAlert`:

| Параметр | Значення |
| --- | --- |
| `enabled` | Увімкнути або призупинити всі сповіщення. |
| `regions` | Список назв регіонів із каналу; `all` означає всі тривоги, порожній список вимикає збіги. |
| `forward_chats` | Список ID або `@username` чатів для пересилання. |
| `nametag` | Необов'язковий підпис під пересланим текстом. |
| `notify_pm` | Надсилати копію в особисті повідомлення свого inline-бота. |
| `repeat_count` | Кількість приватних копій від 1 до 3; типово 1. |
| `repeat_delay` | Затримка між копіями від 1 до 30 секунд. |

Також можна обирати регіони через inline-пошук `@свій_бот alert`,
`@свій_бот alert my` або `@свій_бот alert Полтавська`.
Команда `.alertforward @chat` додає або вилучає чат, `.alertforward` показує
список, а `.alertforward set Мій підпис` змінює підпис.
Попередні списки регіонів і чатів та підпис переносяться до `.config`
під час першого запуску оновленої версії.

## DailyStat

`stats.py` рахує вашу активність у Telegram: надіслані повідомлення в усіх
чатах, вхідні в особистих діалогах, медіа та піки по годинах.

```text
.ds              — кнопкове меню (сьогодні / 7 днів / 30 днів, користувач)
.ds today|week|month
.ds top | .ds peak | .ds peak @username | .ds peak users
.ds scan         — відновити статистику за сьогодні з історії
.ds reset        — скинути всю статистику (з підтвердженням)
```

Підсумок порівнює період із попереднім (вчора / попередні 7 чи 30 днів) і
показує серію днів поспіль, коли ви писали повідомлення.

Звіти показують лише імена: без посилань на профілі, @юзернеймів чи ID, тож
їх можна показувати в інших чатах. Юзернейм зберігається локально тільки для
пошуку `.ds peak @username`. Денні, тижневі й місячні звіти публікуються в
приватний канал «DailyStat • Reports» о `report_hour`; звіт, пропущений через
вимкнений Hikka, надсилається після запуску. Дані, старші за `keep_days`
(типово 120 днів), видаляються автоматично.

## VideoDownloader

`vdlt.py` автоматично завантажує відео, фото й музику з YouTube, TikTok,
Instagram, X, Reddit, Pinterest, Spotify, SoundCloud та інших сайтів у
дозволених групах (`.vdladd`) і особистих чатах (`.vdlpm`).

- Повторне посилання надсилається **з кешу миттєво**, без нового завантаження
  (`.vdlset cache 72` — годин, `0` вимикає; з `auto_delete` кеш не працює).
- З одного повідомлення завантажується до `links` посилань (типово 3).
- `.vdlinfo URL` — назва, автор, тривалість і доступні якості без завантаження.
- `.vdlqueue` / `.vdlcancel` — стан черги та скасування завдань, що чекають.
- `.vdlset workers 3` змінює кількість паралельних завантажень, не перериваючи
  поточні; значення `.vdlset` перевіряються до збереження.
- Статистика (`.vdlstats`) і денний ліміт зберігаються після перезапуску;
  кулдаун рахується окремо для кожного користувача.
- Кожне завдання працює у власній теці `.vdl_work/…`, яка видаляється після
  надсилання; залишки після збою прибираються під час запуску.
- `ig_password` і `cobalt_api_key` приховані в `.config`.
- **Разом із VoiceChat.** Якщо завантажено VoiceChat і його віртуальний
  браузер (`.vcbrowser`) тримає сесію YouTube, VideoDownloader бере cookies
  YouTube саме звідти (кожне завантаження отримує окрему копію, тож сесію
  ротує лише браузер VoiceChat). Коли YouTube просить підтвердити, що це не
  бот, сесію оновлює браузер VoiceChat, а не Firefox VideoDownloader; якщо
  браузер VoiceChat уже оновлює її, модуль чекає на це оновлення. Cookies
  інших сайтів і Firefox для них лишаються як були. Якщо на одній Hikka
  працює кілька акаунтів, VoiceChat шукається на всіх: спершу на своєму
  акаунті, потім на інших (перевага — браузеру з активним входом). Джерело й
  акаунт видно в `.vdlcookies` і `.vdldiag`.

## Wallet P2P

`walletp2p.py` відкриває кнопковий оглядач офіційного Wallet P2P API.
`.p2p` одразу показує оголошення для останнього вибору. У меню можна:

- перемкнути **купівлю / продаж**;
- вибрати криптовалюту й фіат із кнопок або ввести власний код;
- вибрати готову суму або ввести свою, увімкнути фільтр «лише онлайн»;
- побачити найкращу ціну на поточній сторінці, перейти до іншої сторінки чи оновити дані;
- відкрити картку оголошення з лімітами, способами оплати, рейтингом трейдера та кнопкою Wallet.

Модуль запам'ятовує пару, напрямок і фільтри між запусками Hikka. Сортування
за ціною, фільтр суми й онлайн-статусу застосовуються до **поточної сторінки
API** (до 10 оголошень), а не до всіх оголошень ринку. До кожного нового
запиту використовується кеш до 30 секунд; кнопка оновлення робить новий запит.

Створи ключ у Wallet → P2P Market → My Profile → API Keys та заповни приховане
поле `api_key` у `.config WalletP2P` (бажано у «Збережених повідомленнях»).
Без ключа `.p2p` показує інструкцію та кнопки Wallet і документації.
Ключ передається тільки в заголовку `X-API-Key`. За відсутності inline-бота
результат показується як текст.

Wallet API дозволяє **лише перегляд оголошень**. Розміщення, оплата й
підтвердження угоди виконуються в самому Wallet; кнопка відкриває Wallet,
а не конкретне оголошення.

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/walletp2p.py
.p2p
.p2p help
.p2p buy USDT EUR
.p2p sell USDT UAH 500
```

## ModuleHub

`modulehub.py` додає єдиний owner-only центр керування модулями через inline-бота. Він автоматично показує актуальні команди завантажених модулів і підтримує:

- категорії, пошук та пагінацію команд;
- запуск команд з аргументами або у відповідь на повідомлення;
- каталог модулів `Splaueef/host` зі встановленням та оновленням;
- встановлення за короткою назвою чи перевіреним HTTPS-посиланням на `.py`;
- налаштування всіх зовнішніх і системних модулів Hikka;
- перемикачі Boolean, перевірку значень штатними валідаторами й скидання до типового;
- повне приховування API-ключів та інших `Hidden`-параметрів;
- підтвердження встановлення, видалення й інших небезпечних дій;
- локальну інтеграційну шину для інших модулів;
- автоматичний облік запусків команд усіх завантажених модулів;
- пакетну синхронізацію агрегованих метрик і коротких snapshot у HikkaNet.

`ModuleHub` не відправляє текст Telegram-команд, аргументи, повідомлення,
chat/user ID, токени чи session. У HikkaNet ідуть лише назва модуля, назва
лічильника, числове значення та безпечні агрегати, які модуль явно повернув із
`modulehub_stats()`.

### Автоматичне оновлення модулів

`ModuleHub` звіряє встановлені модулі з HTTPS-manifest
`module_versions.json`: перша перевірка виконується приблизно через 90 секунд
після запуску Hikka, наступні — типово кожні 6 годин. Якщо у каталозі є новіша
версія, ModuleHub послідовно запускає штатний Loader для її встановлення.

- оновлюються лише вже встановлені модулі з каталогу `Splaueef/host`;
- відсутні модулі автоматично не встановлюються;
- старіша версія з репозиторію не замінює новішу локальну;
- результат або помилка надходить у «Збережені повідомлення»;
- кнопка `♻️ Автооновлення` у `.modmenu` запускає перевірку вручну;
- `auto_update_exclude` у `.config ModuleHub` виключає вибрані модулі;
- `auto_update_interval` змінює інтервал, а `auto_update_notify` — сповіщення.

Сам `ModuleHub` оновлюється вручну через `.dlmod`, щоб він не вивантажував
власний процес посеред перевірки інших модулів.

Відкрити панель: `.modmenu`.

Встановити окремо:

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/modulehub.py
```

## HikkaNet та окремий Hikka Hub сервіс

`hikkanet.py` підключає Hikka до окремого API-процесу з каталогу
`hikka_hub/`. Сервіс слухає задані IP та порт і дає авторизованим Hikka
heartbeat, список online-вузлів, обмін подіями й JSON-даними, власні метрики та
загальну статистику. Hikka Hub 2.0 також тримає авторитетний стан глобальних
партій, перевіряє кожен хід і веде спільний рейтинг гравців. Підтримуються
хрестики-нулики, шашки, шахи та ґо 9×9/13×13; відкриту партію можна знайти з
будь-якого чату, а приватну — адресувати конкретному `instance_id`.

Кожна інсталяція має окремі `instance_id`, `key_id` і `key_secret`, прив'язані
до Telegram ID її власника. Усі API-запити підписуються HMAC-SHA256 і мають
timestamp та одноразовий nonce; ключ однієї Hikka можна відкликати або ротувати
без відключення інших. Повна інструкція Docker, systemd, видачі ключів і API:
[`hikka_hub/README.md`](hikka_hub/README.md).

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/hikkanet.py
.hknet
```

### Каталог модулів HikkaNet

HikkaNet 2.2 (потрібен Hikka Hub 2.1) має власний каталог модулів. Свій модуль
можна завантажити прямо в HikkaNet — надішли `.py` файл із підписом
`.hkpublish` або відповідай цією командою на файл. Інші користувачі мережі
знаходять його в `.hkmods` і встановлюють кнопкою або командою — без посилань
на GitHub. Модуль ставиться через стандартний завантажувач Hikka і
зберігається після перезапуску.

```text
.hkmods                        — каталог: пошук, сортування, оцінки, встановлення
.hkmods погода                 — пошук за назвою, описом, автором чи тегом
.hkinstall weather             — встановити останню версію
.hkpublish #fun #tools | Що нового  — опублікувати модуль або нову версію
.hkmymods                      — мої модулі; .hkunpublish id [версія]
.hkupdates                     — оновлення встановлених із каталогу модулів
.hkdm hikka-friend Привіт!     — особисте повідомлення іншому вузлу; .hkinbox
```

Перед встановленням Hikka Hub без запуску коду перевіряє модуль і попереджає,
якщо він виконує `eval`/`exec`, запускає системні команди, звертається до
сесії Telegram, змінює файли тощо — такі модулі встановлюються лише після
підтвердження (`-y` або кнопкою). Контрольна сума SHA-256 перевіряється перед
завантаженням. Про нові версії встановлених модулів HikkaNet повідомляє у
«Збережених»; `.config HikkaNet` → `catalog_auto_update` вмикає автооновлення
версій без попереджень.

### HikkaNetChat

`hikkanetchat.py` — окремий модуль кімнат для спілкування між Hikka, яким
адміністратор Hikka Hub видав індивідуальні ключі. Він використовує готове
HMAC-підключення модуля `HikkaNet`, тому не бачить і не копіює `key_secret`.

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/hikkanetchat.py
.hkchat
.hkjoin lobby
.hksay Привіт усім!
.hkhistory lobby
```

Кімнати мають назви з `a-z`, цифр, `_` або `-`. Нові повідомлення з підключених
кімнат надходять у «Збережені повідомлення»; це вимикається через
`.config HikkaNetChat`. HMAC автентифікує відправника, але не шифрує вміст —
через Інтернет використовуй HTTPS або VPN.

HikkaNetChat 2.0 реєструє короткоживу присутність у кімнатах, показує online-
учасників і глобальний список кімнат із кількістю повідомлень за 24 години.
Нові повідомлення всіх підписаних кімнат читаються одним cursor-потоком, тому
кількість API-запитів не росте разом із кількістю кімнат.

```text
.hkrooms
.hkmembers lobby
```

## GroupAdmin

`group_admin.py` додає owner-only панель керування групою або каналом. Якщо
відкрити `.gadmin` у відповідь на повідомлення користувача, у панелі з'являться
кнопки mute/unmute, warn/unwarn, kick, ban і unban. Окремі екрани керують slow
mode, дозволами звичайних учасників і закріпленням повідомлень. Небезпечні дії
потребують підтвердження, а паралельні натискання захищені блокуванням.

Командні скорочення мають префікс `g`, щоб не перезаписувати стандартні модулі
Hikka: `.gban`, `.gkick`, `.gmute`, `.gwarn`, `.gslowmode`, `.glock` тощо.

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/group_admin.py
```

## MiniGames

`minigames.py` містить публічні для учасників чату inline-ігри: хрестики-нулики,
камінь–ножиці–папір із прихованим вибором, кубик-дуель, шашки 8×8, шахи, ґо на
дошках 9×9 і 13×13 та швидку вікторину. У шашках підтримуються обов'язкове
взяття, серії взяттів, удари назад звичайною шашкою та «літаючі» дамки. Шахи
підтримують шах, мат, пат, рокіровку, взяття на проході, перетворення пішака,
правило 50 ходів і триразове повторення позиції. На Telegram із підтримкою Bot
API 10.3 усе меню та всі локальні й HikkaNet-ігри показуються як справжні
**Rich Messages**. Хрестики-нулики, шашки, шахи й ґо мають компактні таблиці,
а КНП, кубик і вікторина — вбудовані в повідомлення інтерактивні кнопки.
Усі вільні клітинки Rich-дошок використовують premium emoji
`5220005833110199517`.
У ґо камінь ставиться одним дотиком до вільної точки на дошці 9×9 або 13×13;
двоетапний вибір рядка й стовпця лишається тільки сумісним fallback-режимом.
У шахах є координати, підсвічування ходів, перевертання дошки та підтвердження
завершення партії; клітинки взяття використовують сумісну з Telegram for iOS
клікабельну червону позначку. У HikkaNet чорні автоматично бачать свою сторону
знизу. Якщо Rich Messages недоступні, модуль автоматично повертається до
сумісної inline-панелі.
У ґо є захоплення груп,
заборона самогубства й повторення позиції, пас і китайський підрахунок території
з комі 6.5. Завершені матчі потрапляють у локальний рейтинг чату. Меню
відкривається командою `.games`; суперника можна запросити відповіддю або через
`@username`.

## AgentBot

`agentbot.py` перетворює особисті повідомлення акаунта на спільну «підтримку»:

1. Під час першого запуску модуль сам створює форум-групу з гілками
   (назва — `group_title` у `.config AgentBot`) і записує в її опис мітку
   `#AgentBot:<ваш ID>`. Після перезапуску, перевстановлення чи втрати бази
   модуль знаходить свою групу за цією міткою й не створює нову.
2. Коли хтось пише вам в особисті, у групі з'являється гілка
   `ID · Ім'я`. Першим повідомленням у ній іде картка співрозмовника: ім'я, ID,
   усі username, телефон (якщо видимий), біо, статус, Premium, чи є контактом,
   кількість спільних чатів, позначки (бот, scam, fake…), DC і фото профілю.
3. Усі наступні повідомлення співрозмовника (текст і медіа) копіюються в його
   гілку; відповідь на повідомлення зберігає зв'язок відповіді.
4. Будь-який учасник групи — не лише власник — пише в гілку, і модуль
   надсилає той самий текст чи медіа співрозмовнику від вашого акаунта. Якщо
   доставка не вдалася (блокування, обмеження приватності), у гілці з'явиться
   попередження.

Повідомлення від службового акаунта Telegram (777000, коди входу) ніколи не
потрапляють у групу. Боти за замовчуванням ігноруються (`ignore_bots`), контакти
можна вимкнути через `ignore_contacts`. Видалену гілку модуль створить заново
при наступному повідомленні. Команди Hikka, які власник пише в гілці
(`.щось`), співрозмовнику не надсилаються.

```text

.agentbot on | off     — увімкнути / призупинити пересилання
.agentbot invite       — запрошувальне посилання для команди
.agentbot forget [ID]  — відв'язати гілку (у гілці можна без ID)
.agentbot new          — створити нову групу замість поточної
```

## VoiceChat

`voicechat.py` приєднує ваш акаунт до групового дзвінка (відеочату) у групі чи
каналі й транслює туди відео або музику. Відео типово показується **як
демонстрація екрана** — велике вікно в дзвінку (`video_mode=screen`; `camera`
показує його як відео з камери). Якщо дзвінок ще не почався, модуль його
створить (потрібне право керувати дзвінками).

**Джерела.** Посилання на YouTube, будь-який із ~1800 сайтів yt-dlp,
пошуковий запит або аудіо / відео з Telegram (відповіддю на повідомлення).
Якщо yt-dlp сайт не знає, модуль сам читає сторінку: теги `<video>` /
`<source>`, `og:video`, посилання на потоки в конфігах плеєрів (JW Player,
Playerjs, Plyr, Video.js…), а далі — вбудовані плеєри в `<iframe>` (до двох
рівнів вкладеності), передаючи їм потрібні Referer / Origin / User-Agent.
HLS із сегментами під виглядом `.jpg`/`.txt` теж відтворюється. Захищені
плеєри, які шифрують посилання, модуль не обходить.

**Файли з Telegram грають одразу.** Відповідь `.vcplay` / `.vcadd` на відео чи
аудіо не чекає, доки файл скачається: модуль віддає його ffmpeg через
локальний HTTP-сервер (`127.0.0.1`) із підтримкою Range, а файл тим часом
качається з Telegram у **кілька паралельних потоків** (`tg_workers`, типово 4)
у спільний кеш на диску. Спершу — шматки біля поточної позиції, потім решта
файлу у фоні, тож звук і відео (py-tgcalls читає їх окремими ffmpeg) і
перемотування беруть уже скачане, а не тягнуть ті самі байти знову. Перед
стартом набирається буфер на `tg_prebuffer` секунд (типово 8) — у
повідомленні видно відсоток і швидкість, у `.vcnow` — скільки скачано.
MP4 з індексом у кінці файлу працюють; кеш видаляється після треку. Якщо на
диску немає місця, файл іде потоком без кешу. З `tg_stream=false` файл
спершу повністю завантажується, з прогресом.

**Кодеки.** Перед відтворенням ffprobe визначає справжні кодеки (H.264, H.265,
VP9, AV1, AAC, Opus, AC-3…), роздільність, частоту кадрів, тривалість і чи є
відео- та звукова доріжки — усе це видно в `.vcnow` і повідомленні «Зараз
грає». ffmpeg декодує будь-який із підтримуваних ним форматів; відео без
звуку чи звук без відео теж працюють.

**Якість.** Береться найкращий потік джерела, але не вище `video_quality`
(типово `1080p`) і `max_fps` (типово 30). Відео кодується на сервері в
реальному часі, тому 4K чи 60 кадрів/с потребують дуже потужного процесора —
інакше звук іде, а картинка зависає. Звук — 48 кГц стерео
(`audio_quality=high`), максимум для кодека Opus у дзвінках. `.vcaudio`
навмисно вмикає лише звук.

**Перепідключення.** Якщо зв'язок із дзвінком обірвався (мережа, сервер
Telegram) або потік завис без звуку й відео, модуль сам виходить із дзвінка,
заходить знову й продовжує трек з того ж місця, повідомивши про це в чат.
Після кількох невдалих спроб поспіль він виходить із дзвінка й пише про це.

```text
.vcplay <посилання | запит>   — увімкнути зараз (замінює те, що грає)
.vcplay -a … / .vcaudio …     — лише звук
.vcadd <посилання | запит>    — додати в чергу; плейлисти YouTube теж
.vcsearch <запит> [-a]        — пошук на YouTube: 5 результатів кнопками
.vcnow                        — панель керування з кнопками
.vcpause / .vcresume          — пауза / продовжити
.vcskip                       — наступний трек
.vcseek 1:30 | +15 | -10      — перемотати
.vcvol 1-200                  — гучність
.vcloop                       — повтор поточного треку
.vcaudiotrack [N]             — звукові доріжки (озвучки) і вибір
.vcqueue / .vcclear           — черга, очистити чергу
.vcremove N / .vcmove N M     — прибрати / пересунути трек у черзі
.vcstop                       — зупинити й вийти з дзвінка
.vcstats                      — навантаження сервера й чи встигає відео
.vcradio [on [канал] | off | reload] — радіо: музика з каналу по колу
.vcsetup                      — встановити / оновити залежності
```

**Панель керування.** Замість окремих повідомлень модуль показує одну
панель (через inline-бота Hikka), що оновлюється кожні 15 секунд: назва,
прогрес, якість, кодеки, гучність, що далі, і кнопки ⏪ 10 · ⏸/▶️ · 10 ⏩,
🔉 · ⏭ · 🔊, 🔁 · 🎚 · 📜 · ⏹. `.vcnow` переносить панель униз чату.
Вимикається `panel=false`.

Панель типово оформлена як **Telegram Rich Text** (`panel_style=rich`):
заголовок із назвою, рядок прогресу, таблиця зі станом, гучністю, повтором,
якістю, чергою й радіо, блок «Далі» та кольорові кнопки прямо в повідомленні
(⏸/▶️ — синя, ⏭ — зелена, ⏹ — червона, 🔁 — зелена, коли повтор увімкнено).
Якщо Telegram не приймає Rich-повідомлення, модуль сам повертається до
звичайної панелі; `panel_style=html` вмикає її одразу.

Панель редагує inline-бот Hikka, а Telegram дає йому таку змогу лише тоді,
коли повідомляє, що панель надіслано (inline feedback). Якщо ці повідомлення
не приходять, модуль прибирає застиглу панель і показує текстову з тим самим
вмістом: її редагує сам акаунт кожні 15 с, кнопок у ній немає. У чат приходить
підказка: @BotFather → `/setinlinefeedback` → ваш бот → **Enabled**, потім
`.vcnow` знову пробує панель з кнопками.

**Одне повідомлення «Зараз грає».** Коли трек змінюється (наступний у
черзі, `.vcplay`, `.vcskip`, радіо, відновлення після перезапуску), бот не
надсилає нове повідомлення, а редагує те саме: панель або, з `panel=false`,
текст «Зараз грає». Відповідь на команду лише коротко підтверджує дію. Нове
повідомлення з'являється, тільки якщо старе видалили, або за `.vcnow`.

**Плеєр пам'ятає налаштування.** Гучність, режим радіо, канал радіо й останню
пісню радіо модуль зберігає для кожного чату окремо: вони діють і в наступному
дзвінку, і після перезапуску Hikka.

**Радіо.** У `.config VoiceChat` → `radio_channel` вкажіть канал із музикою —
ID (наприклад `-1002562411082`), `@username` або посилання `t.me/…`; акаунт
має бачити цей канал. Далі адміністратор (власник або `trusted_users`)
вмикає радіо в групі: `.vcradio on`. Бот бере аудіо з каналу (до
`radio_limit` останніх, типово 1000) і грає їх по колу, у випадковому порядку
(`radio_shuffle`) або за порядком каналу, і продовжує з місця, де зупинився.
Пісні йдуть потоком із Telegram без повного завантаження, наступна готується
заздалегідь. Треки, додані через `.vcadd`, грають першими, а потім радіо
продовжується. `.vcradio on @інший_канал` вмикає радіо з іншого каналу для
цього чату, `.vcradio reload` перечитує канал (нові пісні додаються й самі,
на кожному новому колі), `.vcradio off` вимикає радіо (поточна пісня
дограє), `.vcstop` зупиняє все разом із радіо. Увімкнене радіо
переживає перезапуск Hikka.

**Озвучки.** Якщо у файлі кілька звукових доріжок (MKV з дубляжем),
модуль сам обирає першу мову з `audio_languages` (типово `uk`, `ukr`; також
шукає мову в назві доріжки). `.vcaudiotrack` показує доріжки, `.vcaudiotrack 2`
перемикає без втрати позиції, кнопка 🎚 на панелі — по колу.

**Звук** іде без фільтрів, як в оригіналі (48 кГц стерео); гучність —
`.vcvol` або кнопки 🔉/🔊.

**Плавність на слабкому сервері.** Відео кодується в дзвінок у реальному
часі, і це найважча частина роботи. Тому:
- `.vcstats` під час відтворення показує навантаження процесора (окремо
  Hikka з кодуванням відео й ffmpeg з декодуванням), пам'ять і чи є запас;
- `auto_quality` (типово увімкнено): якщо процесор зайнятий на 90%+ пів
  хвилини поспіль, роздільність знижується на крок (1080p → 720p → 480p…), і
  трек продовжується з того ж місця; у чат приходить повідомлення. Наступний
  трек повертається на крок вище, коли процесор звільнився (до 55%);
- декодування відео обмежене половиною ядер (`decode_threads`, 0 — авто),
  щоб решта лишалася для кодування в дзвінок.

**Без пауз і обривів.** Поки грає трек, наступний у черзі вже отримує
посилання й набирає буфер (`prefetch_next`). Якщо потік обірвався задовго до
кінця (мережа, прострочене посилання YouTube), трек перезапускається з того
самого місця (до 3 разів). Завантаження з Telegram при збоях мережі
повторюється з наростаючою паузою.

**Черга після перезапуску.** Черга, поточний трек, позиція, гучність,
повтор і повідомлення «Зараз грає» зберігаються; після перезапуску Hikka модуль сам повертається в
дзвінок і продовжує (`resume_after_restart`, якщо минуло менше 12 годин).
Файли з Telegram відновлюються за посиланням на повідомлення.

**Швидкість і легкість.**
- Старт, перемотування й зміна доріжки не запускають допоміжних процесів:
  потік для py-tgcalls будується з того, що модуль уже знає про трек (раніше
  щоразу — 4 ffprobe, частина з них через мережу, і 2 дампи довідки ffmpeg).
- Повторне посилання (або той самий трек у черзі) відкривається з кешу
  30 хвилин; у кеші — лише потрібні поля, а не весь список форматів.
- Клієнт YouTube, що спрацював, наступного разу пробується першим.
- Файли з Telegram стартують після ~3 с буфера, якщо качаються щонайменше
  вдвічі швидше, ніж грають.
- Lanczos — лише при зменшенні від 1,5 раза; відео рідного розміру не
  масштабується зовсім.
- Позиція зберігається в базу раз на хвилину; yt-dlp, py-tgcalls і список
  опцій ffmpeg прогріваються у фоні через 20 с після запуску.

**Хто керує** (`access`): `owner` — лише власник і `trusted_users`
(для інших модуль мовчить); `queue` — усі учасники групи можуть додавати в
чергу, шукати й дивитися, а керувати — власник і довірені; `all` — усі.
Кнопки панелі й пошуку перевіряють ті самі права.

Команди з посиланням працюють і у відповідь на повідомлення з посиланням або
медіафайлом. Коли черга закінчується, бот виходить із дзвінка (`auto_leave`).

**YouTube і «Sign in to confirm you're not a bot».** YouTube часто вимагає
вхід від серверних IP. Статичний cookies.txt швидко застаріває: Google
постійно ротує cookies сесії, і хто ротував першим (браузер, з якого їх
експортували, VideoDownloader чи VoiceChat), той і лишається з робочою
сесією, а решта копій «вмирає». Тому VoiceChat має **віртуальний браузер**:

```text
.vcbrowser            — стан сесії та інструкція
.vcbrowser setup      — встановити Playwright і Chromium (один раз)
.vcbrowser import     — у відповідь на cookies.txt (або з шляхом до файлу)
.vcbrowser refresh    — оновити сесію зараз
.vcbrowser reset      — видалити профіль браузера
```

Headless Chromium із власним профілем (`.voicechat_browser/`) раз на
`browser_refresh_min` хвилин (типово 30) відкриває YouTube, Google ротує
cookies як у звичайному браузері, і браузер експортує свіжий cookies.txt.
yt-dlp отримує лише **копію** цього файлу, тож сесію ротує тільки браузер.
Якщо YouTube все ж відмовив, браузер одразу оновлює сесію й робить ще одну
спробу. VideoDownloader теж бере YouTube-сесію з цього браузера й не
запускає для YouTube власний Firefox. Щоб сесію не «перебивав» ваш браузер, експортуйте cookies у
приватному вікні (краще окремим акаунтом) і закрийте вікно, не виходячи з
акаунта.

Без віртуального браузера модуль бере cookies так само, як VideoDownloader:
`cookies_file`, cookies VideoDownloader або `/home/rkbot/URKbot/cookies.txt`;
підключає Deno/Node для JS-перевірок YouTube, перебирає клієнти YouTube, а із
застарілими cookies пробує ще й без них.

**Як це влаштовано.** Якщо Hikka працює на звичайному Telethon 1.40+ (як
форк Splaueef/hikka з Telethon 1.44), модуль передає бібліотеці
[py-tgcalls](https://github.com/pytgcalls/pytgcalls) власний клієнт Hikka —
жодних додаткових з'єднань. Оригінальна Hikka працює на `hikkatl` — форку
Telethon зі старою схемою API без сучасних запитів групових дзвінків; тоді
модуль відкриває окреме легке з'єднання upstream Telethon із **тим самим
ключем авторизації** акаунта (без повторного входу й без файлу сесії).

Потрібні `ffmpeg` і `ffprobe` у системі. `.vcsetup` встановлює лише те, чого
бракує (`py-tgcalls`, свіжий `yt-dlp`), і перезапуск після нього не потрібен.
Telethon модуль ставить тільки для збірок на `hikkatl`; Telethon, на якому
працює сама Hikka, ніколи не замінюється.

```text
.dlmod https://raw.githubusercontent.com/Splaueef/host/main/voicechat.py
```
